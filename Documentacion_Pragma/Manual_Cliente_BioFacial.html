Este documento contiene la explicación profunda y técnica de cómo opera el módulo biométrico BioFacial dentro del Sistema de Pago y Contratación Digital (SPCD), diseñado para que el equipo pueda defender y exponer el funcionamiento de la plataforma con máxima propiedad técnica.

1. Arquitectura Biométrica: ¿Cómo funciona realmente?

El sistema no opera tomando ni guardando fotografías convencionales, lo cual evita problemas de privacidad y de peso en la base de datos. La arquitectura se fundamenta en procesamiento de Inteligencia Artificial (IA) en el "Edge" (es decir, en el navegador del usuario) y una validación matemática en la nube.

Proceso de Extracción (Feature Extraction)

Cuando el usuario se registra o intenta pagar, el sistema carga redes neuronales convolucionales (modelos de Deep Learning) utilizando TensorFlow.js en segundo plano. El proceso es:

  1. Detección Facial (tiny_face_detector): Un modelo ultraligero localiza dónde está el rostro en el recuadro del video.
  2. Mapeo Anatómico (face_landmark_68): Un segundo modelo identifica 68 puntos geométricos clave del rostro (ojos, nariz, mandíbula, etc.).
  3. Cálculo Tensorial: El modelo principal traduce esas facciones físicas en un arreglo matemático exacto compuesto por 128 números de punto flotante (decimales).

Este arreglo de 128 números se llama Descriptor Facial. Es el equivalente biométrico de un "Código Hash" o huella dactilar digital. Es completamente irreversible; no se puede recrear una cara a partir de esos números.

El Algoritmo de Verificación Matemática

En la base de datos solo se guardan estos descriptores matemáticos. Al momento de procesar un pago, la cámara extrae los 128 números actuales de la persona y los envía al servidor (Backend).

El servidor compara los números enviados desde el punto de venta con los números guardados en la base de datos utilizando una fórmula de cálculo de proximidad llamada Distancia Euclidiana:

d(p, q) = √ (Σ (pi - qi)²)

El algoritmo cruza cada uno de los 128 números. Si el margen de diferencia geométrica es menor a 0.45, el servidor tiene certeza matemática de que es la misma persona y procesa el cobro instantáneamente.

2. Niveles de Seguridad (Blindaje)

El ecosistema SPCD ha sido diseñado con una arquitectura segura (Zero-Trust) implementada por Pragma Studio para resistir ataques e inspecciones:

2.1 Seguridad de Interfaz (Frontend)

El cliente web está blindado contra manipulación de usuarios y bloqueos de seguridad anti-depuración. Están deshabilitadas las herramientas de desarrollo, el clic derecho y las combinaciones de inspección del navegador para asegurar la integridad de la interfaz durante las operaciones.

2.2 Seguridad del Servidor (Railway)

El motor de pagos se ejecuta en un contenedor en la nube. Sus defensas incluyen:

  • Helmet (Protección de Cabeceras): Se encriptan y configuran las cabeceras de red para impedir inyecciones de código malicioso (XSS) y Clickjacking.
  • Rate-Limiting (Prevención DDoS): El servidor cuenta con un cortafuegos activo. Si detecta múltiples peticiones rápidas desde un mismo origen (intentos de forzar pagos o tirar el servidor), bloquea automáticamente la dirección IP del atacante.

3. Flujo de Uso para la Demostración

Durante la exposición, sigan este flujo exacto para demostrar el sistema:

  1. Apertura de la Base de Datos: Abran la consola de MongoDB en su navegador. Se les ha provisto de un acceso de Solo Lectura. Esto permite mostrar al jurado en vivo cómo se registran los usuarios en tiempo real, garantizando que el sistema es auditable pero sin el riesgo de que se elimine o altere la base de datos por error.
  2. Registro (BankUnerg): Ingresen los datos de una persona y realicen el registro biométrico. El sistema guardará su descriptor en la base de datos al instante.
  3. Compra (BodeUnerg): Agreguen productos al carrito de prueba. Procedan al pago seleccionando "Reconocimiento Facial". El sistema leerá el rostro y aprobará el pago en menos de un segundo al validar matemáticamente la identidad.
