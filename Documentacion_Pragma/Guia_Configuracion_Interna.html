Guía Interna de Configuración y Blindaje (Solo para ti)

Esta guía es exclusiva para ti (Pragma Studio). Aquí te explico exactamente qué le hicimos al código fuente para blindarlo y cómo debes configurar la base de datos de MongoDB Atlas para entregársela al cliente lista para la exposición.

1. Lo que ya está blindado en el código fuente

He modificado el código del proyecto directamente en tu entorno para que el blindaje esté 100% activo:

  1. Anti-Inspección (Frontend): En BankUnerg/index.html y BodeUnerg/index.html agregué un script invisible que bloquea el clic derecho, bloquea presionar F12 y bloquea las combinaciones de teclas (Ctrl+Shift+I, Ctrl+U). Así el jurado no podrá hurgar el código fuente en vivo.
  2. Autoría Intelectual (Frontend): En los archivos App.tsx de ambos proyectos, incrusté al final tu marca de agua fija: "Diseñado y desarrollado por PRAGMA STUDIO, se reserva el derecho de autor."
  3. Seguridad del Backend (server.js):
    • Instalé la librería helmet y la habilité como middleware. Esto encripta las cabeceras HTTP cuando se despliega en Railway.
    • Instalé express-rate-limit y lo configuré para el endpoint /api/. Si alguien hace más de 150 peticiones en 15 minutos, queda bloqueado. Esto previene ataques DDoS o de fuerza bruta.

2. Configuración de la Base de Datos (LO QUE DEBES HACER TÚ)

Para que el cliente (Carpio y su equipo) pueda abrir la base de datos y mostrar cómo se añaden los descriptores faciales en tiempo real sin que puedan borrar o alterar nada, debes crearles un usuario con permiso estricto de Solo Lectura (Read-Only).

Sigue estos pasos en tu cuenta de MongoDB Atlas para configurarles el acceso:

  1. Inicia sesión en MongoDB Atlas con tu cuenta de administrador.
  2. Asegúrate de estar en el Proyecto/Clúster correcto (donde corre la BD biofacial).
  3. En el panel izquierdo, busca la sección de Security y haz clic en Database Access.
  4. Haz clic en el botón verde de la derecha: ADD NEW DATABASE USER.
  5. Selecciona el método de autenticación por Password.
  6. En Username, coloca algo como: exposicion_lectura (o el nombre que quieras darles).
  7. En Password, genera una contraseña segura (ej: BioFacial_Pragma2026). Copia este usuario y clave en un bloc de notas para dárselo al cliente.
  8. En la sección de Database User Privileges, abre el menú desplegable y elige el rol: "Only read any database" (o "read" en Custom Role).
    Paso Crítico: Esto garantiza que puedan hacer consultas y ver los datos en vivo, pero si intentan borrar o modificar un usuario, MongoDB se los prohibirá.
  9. Haz clic en Add User al final para guardar.
  10. (Opcional pero recomendado): Ve a Network Access y asegúrate de que la IP desde la que ellos van a exponer esté permitida (o si está en 0.0.0.0/0, no hay problema).

¿Qué les entregas a ellos?

Una vez configurado este usuario, les entregas el manual para el cliente junto con las credenciales que acabas de crear (exposicion_lectura y su contraseña).

Diles que el día de la presentación inicien sesión en la base de datos usando esas credenciales y abran la colección users para verla en vivo.
